# ADR-001: CoreS3 SD 卡采用显式 SPI3 handoff

## 状态

Accepted

## 背景

CoreS3 的 SD 卡和显示链路共享 SPI3 相关 GPIO 矩阵资源，其中 GPIO35 也参与显示 D/C 路径。StackChan 启动显示后直接初始化 SD，会出现 `esp_err_timeout`、`raw sector read failed` 或容量读取异常；而 CoreS3 原厂程序可以正常读卡，说明硬件和 FAT32 卡本身不是首要故障点。

## 决策

在访问 SD 前显式执行显示总线释放和 SD 总线接管；SD 访问结束后再恢复显示需要的矩阵状态。挂载始终使用只读策略，不允许自动格式化。SD 供电通过 CoreS3 官方电源路径重新启用后再挂载。

## 备选方案

### 重新格式化 SD 卡

拒绝。用户的卡还要供另一块 ESP32 HiFi 开发板使用，格式化会破坏现有内容，而且不能修复 GPIO 资源争用。

### 改用不同 SD 引脚

拒绝。CoreS3 插槽的硬件布线固定，改脚会脱离官方硬件设计，且无法解释原厂固件可正常访问这一事实。

### 只增加重试次数

拒绝。重试可以掩盖时序问题，不能解决显示矩阵仍占用 GPIO35 的根因。

## 影响

- SD 初始化与显示初始化存在明确顺序要求，后续新增媒体功能必须复用 handoff 接口。
- 访问 SD 时需要避免同时进行显示 SPI 事务。
- 只读挂载降低了共享卡被意外修改的风险，但不能替代正常弹出/断电流程。
